# 基于InsightFace与浏览器插件的B站视频明星人脸识别系统设计与实现

> 毕业设计论文 · 配套项目工程见本仓库根目录（`backend/`、`extension/`、`data/`）

## 摘要

随着视频平台的快速发展，用户在观看综艺、访谈、影视剪辑等内容时，常对画面中出现的明星产生好奇，但依靠手动搜索效率低下。本文设计并实现了一套面向B站视频的明星人脸识别浏览器插件系统。系统采用"浏览器插件 + 本地识别服务"的双端混合架构：前端基于 Chrome Manifest V3 规范开发，负责视频帧捕获、识别请求发送与结果叠加渲染；后端基于 Python Flask 框架与 InsightFace 深度学习库，负责对人脸进行检测（RetinaFace）、特征提取（ArcFace，512维向量）并与本地明星特征库进行余弦相似度比对，最终在视频画面上实时显示明星姓名。系统全部图像数据仅在本机回环地址传输，不经过任何外部网络，充分保护用户隐私。测试结果表明，系统能够稳定识别已入库明星并在全屏、多分辨率等场景下正确渲染标签，满足需求文档设定的功能与性能指标。本文还详细阐述了系统从需求分析、架构设计到逐模块代码实现的完整过程，可作为人脸识别技术落地应用的参考范例。

**关键词**：人脸识别；InsightFace；Chrome插件；Flask；特征向量；余弦相似度

---

## Abstract

With the rapid development of video platforms, users often become curious about the celebrities appearing in variety shows, interviews, and movie clips, but manual searching is inefficient. This thesis designs and implements a celebrity face recognition browser extension system for Bilibili videos. The system adopts a hybrid architecture of "browser extension + local recognition service": the frontend, developed based on Chrome Manifest V3 specification, is responsible for video frame capture, recognition request sending, and result overlay rendering; the backend, based on Python Flask framework and the InsightFace deep learning library, is responsible for face detection (RetinaFace), feature extraction (ArcFace, 512-dimensional vector), and cosine similarity comparison against a local celebrity feature database, finally displaying celebrity names on the video screen in real time. All image data of the system is transmitted only through the local loopback address without passing through any external network, fully protecting user privacy. Test results show that the system can stably recognize registered celebrities and correctly render labels in full-screen and multi-resolution scenarios, meeting the functional and performance indicators set by the requirements document. This thesis also elaborates the complete process from requirements analysis and architecture design to module-by-module code implementation, which can serve as a reference example for the practical application of face recognition technology.

**Keywords**: Face Recognition; InsightFace; Chrome Extension; Flask; Feature Vector; Cosine Similarity

# 第1章 绪论

## 1.1 研究背景与意义

哔哩哔哩（B站）是中国领先的年轻一代视频社区，其内容涵盖综艺、访谈、影视剪辑、UP主原创等多个品类。在这些视频中，经常出现大量明星人物。对于普通观众而言，当画面中突然出现一位"眼熟但叫不出名字"的演员或歌手时，往往需要暂停视频、打开搜索引擎、输入描述性关键词进行查找，过程繁琐且容易打断观看体验。

人脸识别技术经过数十年的发展，尤其是2014年以来深度学习方法的突破，识别精度已大幅超越人眼水平。目前人脸识别已在安防、支付、考勤等场景得到大规模商用，但面向普通用户的"观剧识人"类轻量应用仍然较少，主要原因在于：一是深度学习模型体积大、算力要求高，难以直接在浏览器等终端运行；二是将视频帧上传云端处理存在隐私与成本顾虑。

在此背景下，本文设计并实现了一个**本地化、低门槛、可扩展**的明星人脸识别浏览器插件：

- **本地化**：识别全部在本机完成，视频帧不离开用户设备，从根源上消除隐私风险；
- **低门槛**：用户只需安装浏览器插件并运行一个本地服务脚本，无需了解任何深度学习知识；
- **可扩展**：明星特征库独立于插件本体，更新明星名单只需重建数据文件，无需重装插件。

该项目既是人脸识别技术的轻量落地实践，也是一个覆盖"前端插件开发、后端服务开发、深度学习模型调用、算法理解、系统测试"完整链条的工程案例，对初学者具有很强的学习价值——这正是本文选择以"让初学者能看懂"为标准撰写的原因。

## 1.2 国内外研究现状

### 1.2.1 人脸识别技术的发展

人脸识别问题可拆解为三个子问题：**人脸检测**（在哪里）、**特征提取**（长什么样）和**身份比对**（是谁）。

- **传统方法阶段**：早期方法依赖人工设计特征，如特征脸（Eigenface，基于PCA）、局部二值模式（LBP）、方向梯度直方图（HOG）配合支持向量机（SVM）分类器。这类方法对光照、姿态、遮挡变化敏感，精度有限。
- **深度学习阶段**：2014年 Facebook 的 DeepFace 首次将深度卷积神经网络引入人脸验证并接近人类水平；2015年 Google 的 FaceNet 提出用三元组损失训练网络，将人脸映射为欧氏空间中可直接比较的嵌入向量（embedding）；2019年 Deng 等人提出 ArcFace，在 Softmax 分类损失中引入加性角度间隔，显著提升了识别精度，成为工业界主流方案。
- **开源生态**：InsightFace 项目开源了包括 RetinaFace（检测）与 ArcFace（识别）在内的一整套训练好的模型与推理工具，研究者无需自己训练即可获得高精度的人脸识别能力，本文即基于该库实现。

### 1.2.2 浏览器端人脸识别的方案对比

在浏览器中识别人脸主要有三条技术路线，对比见表1-1。

**表1-1 浏览器端人脸识别方案对比**

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 纯浏览器端（TensorFlow.js / face-api.js） | 免安装、无服务依赖 | 模型体积大、精度与速度受限、跨平台兼容性问题多 | 轻量演示 |

本文选择第三条路线：浏览器负责轻量的界面与交互，复杂的模型推理交给本机 Python 服务，既保证了识别精度，又守住了隐私底线。

# 第2章 相关技术基础

本章面向初学者，介绍理解本系统所需的背景知识。已熟悉相关技术的读者可略过。

## 2.1 人脸识别技术概述

人脸识别（Face Recognition）的完整流程如图2-1所示：

```plaintext
输入图像 ──▶ 人脸检测 ──▶ 人脸对齐 ──▶ 特征提取 ──▶ 特征比对 ──▶ 身份结果
           (在哪里)      (摆正/归一)    (变成向量)    (和库中向量比)
```

1. **人脸检测（Face Detection）**：在图像中定位所有人脸的位置，输出包围人脸的矩形框（bounding box）。本系统使用 RetinaFace 模型完成。
2. **人脸对齐（Face Alignment）**：根据检测到的关键点（眼睛、鼻子、嘴角）将人脸旋转、缩放到统一尺寸，消除姿态差异。InsightFace 的推理管线自动完成该步骤，对使用者透明。
3. **特征提取（Feature Extraction）**：将对齐后的人脸输入深度卷积网络，输出一个固定维数的向量（本系统为 512 维），称为**特征向量（embedding）**。同一个人的不同照片，其特征向量在空间中彼此靠近；不同人的特征向量相互远离。这一步是把"人脸长什么样"转化成"计算机可计算的数字"。
4. **特征比对（Feature Matching）**：将待识别脸的特征向量与特征库中所有已知明星的向量逐一计算相似度，取最高者，若超过设定阈值则判定为该明星，否则判定为"未知"。

**关键概念：相似度阈值**。识别不是非黑即白，而是连续的相似度分数。阈值设得高，则"宁可不认"（误认少、未知多）；阈值设得低，则"大胆猜测"（认得多、易误认）。本系统默认阈值 0.60，并允许用户在插件面板中实时调整。

## 2.2 InsightFace 与 buffalo_l 模型

[InsightFace](https://github.com/deepinsight/insightface) 是由中科院计算所团队开源的人脸分析工具库，提供人脸检测、识别、属性分析等一整套开箱即用的能力。本系统使用其中的两个核心模型（打包在 `buffalo_l` 模型包中）：

| 模型 | 作用 | 输出 |
|------|------|------|
| RetinaFace | 人脸检测 | 人脸边界框 + 5 个关键点 |
| ArcFace（recognition） | 特征提取 | 512 维归一化特征向量 |

在代码层面，InsightFace 提供了高度封装的 `FaceAnalysis` 类：

```python
from insightface.app import FaceAnalysis
app = FaceAnalysis(name='buffalo_l', providers=['CPUExecutionProvider'])
app.prepare(ctx_id=0, det_size=(640, 640))
faces = app.get(image)          # 传入 BGR 图像，返回人脸列表
face.bbox                      # [x1, y1, x2, y2] 人脸框
face.embedding                 # 512 维特征向量 (numpy 数组)
```

对使用者而言，检测与特征提取被封装为一行 `app.get(image)`，这正是本系统能快速搭建的原因。模型文件在首次运行时自动从官方源下载至 `~/.insightface/models/`，无需手动配置。

> **对初学者的提示**：`image` 的通道顺序是 BGR（蓝绿红）而非常见的 RGB，这是 OpenCV 的历史约定。本系统全链路使用 OpenCV 处理图像，因此保持一致即可，无需额外转换。

## 2.3 Chrome 浏览器插件（扩展）技术

### 2.3.1 插件的组成部分（Manifest V3）

一个 Chrome 插件由以下部分构成（见图2-2）：

```plaintext
┌────────────────────────── Chrome 插件 ──────────────────────────┐
│  manifest.json（清单：声明插件身份、权限、入口）                  │
│                                                                  │
│  ├── content script  注入到网页中的脚本，可读写网页 DOM           │
│  ├── popup           点击工具栏图标弹出的设置面板                 │
│  └── service worker  后台常驻逻辑（MV3 用 Service Worker 替代     │
│                      旧版的 background page）                    │
└──────────────────────────────────────────────────────────────────┘
```

- **manifest.json**：插件的"身份证"，声明插件名称、版本、需要的权限（permissions）、可以访问的网站（host_permissions）、各组件入口文件等。所有声明必须在这里登记，否则功能不可用——这是 Chrome 的安全机制。
- **Content Script（内容脚本）**：被注入到指定网页中运行的脚本。它生活在一个"隔离世界"中，可以操作页面 DOM（比如找到 `<video>` 元素、往页面上画标签），但不会与页面自身的 JavaScript 变量互相污染。
- **Popup**：用户点击工具栏图标时弹出的 HTML 页面，适合放置设置界面。通过 `chrome.storage` 与 content script 共享配置。
- **Service Worker**：插件级的后台进程，用于处理全局事件（如消息、快捷键）。MV3 中为节省资源，Service Worker 在不工作时会被休眠。

### 2.3.2 权限模型

插件想做什么，必须先在 manifest 中申请：

```json
"permissions": ["storage", "tabs"],
"host_permissions": ["http://127.0.0.1/*", "http://localhost/*"]
```

- `storage`：允许使用 `chrome.storage` 持久化配置；
- `tabs`：允许查询当前标签页（popup 判断当前页面是否为B站）；
- `host_permissions`：允许插件脚本访问指定网址。这里只申请了本机回环地址（127.0.0.1 / localhost），即插件只能访问本地识别服务，**无法**访问其他任何网站——最小权限原则。

### 2.3.3 插件与本地服务的通信

Content script 向 `http://127.0.0.1:5000` 发请求属于跨域请求。通常浏览器会拦截跨域请求，但插件获得 host_permissions 授权后可以合法访问。为避免任何意外，后端响应同时携带 `Access-Control-Allow-Origin: *` 头（见第5章），双保险。

## 2.4 Flask 与 HTTP 接口

[Flask](https://flask.palletsprojects.com/) 是 Python 生态中最流行的轻量级 Web 框架。本系统用它搭建本地识别服务，核心概念只有三个：

1. **路由（Route）**：用装饰器把"网址 + 方法"绑定到 Python 函数。例如：

```python
@app.route("/health", methods=["GET"])
def health():
    return jsonify({"status": "ok"})
```

访问 `GET http://127.0.0.1:5000/health` 时，Flask 会调用 `health()` 函数并返回 JSON。

2. **请求（Request）与响应（Response）**：插件把图片以 JSON 形式 POST 给服务，服务解析后返回识别结果。本系统全部数据以 JSON（JavaScript Object Notation，一种键值对文本格式）传递，人类可读、跨语言通用。

3. **base64 编码**：图片是二进制数据，不能直接塞进 JSON 文本。解决办法是先用 base64 把二进制转成纯文本（只含字母数字和 `+/=`），再加上前缀 `data:image/jpeg;base64,` 形成"数据URL"。服务端再反向解码还原成图像。一次识别请求的数据格式如下：

```json
POST /recognize
{
  "image": "data:image/jpeg;base64,/9j/4AAQSkZJRg..."
}
```

## 2.5 相似度度量：余弦相似度

特征比对需要一个数学量来衡量两个向量的"接近程度"。本系统使用**余弦相似度（Cosine Similarity）**：

$$\text{similarity}(A,B) = \frac{A \cdot B}{\|A\| \cdot \|B\|} = \frac{\sum_{i=1}^{n} A_i B_i}{\sqrt{\sum A_i^2}\sqrt{\sum B_i^2}}$$

直觉理解：把向量看作从原点出发的一支"箭"，余弦相似度衡量的是两支箭**方向的接近程度**，取值范围 [-1, 1]。方向越一致，值越接近 1，表示越相似。它不关心箭的长度（向量模长），因此对光照等造成向量整体缩放的情况不敏感，非常适合人脸特征比对。

**归一化技巧**：如果把所有向量先除以各自的模长（称为 L2 归一化），那么分母恒等于 1，余弦相似度就退化为**点积**：

$$\text{similarity}(A,B) = A_{\text{norm}} \cdot B_{\text{norm}}$$

点积在代码里就是一行 `np.dot(a, b)`，计算极快。本系统在构建特征库和比对前都做了归一化，正是为了利用这一性质——特征库有 500 人时，逐人点积的总耗时也远小于 1 毫秒，完全不是性能瓶颈。

# 第3章 系统需求分析

## 3.1 系统目标

本系统的核心目标是：**构建一个 Chrome 浏览器插件，在 B 站视频播放过程中自动检测、识别人脸，并在对应人脸位置上方叠加显示明星姓名**，从而免去用户手动搜索的麻烦。

系统范围界定（MVP 版本）：

- 仅支持 B 站视频页面（www.bilibili.com）；
- 识别对象为 100~500 位中国知名明星（本地固定特征库）；
- 不支持其他视频网站，不支持明星库动态在线更新。

- **FR-2/FR-4**：由后端 InsightFace + 特征库完成（见 5.2.2）；
- **FR-3**：本文采用轻量方案——前端按人脸框交并比（IoU）对相邻帧结果做平滑去抖，而非维护完整的多目标跟踪器（见 5.4.4），在效果与复杂度间取得平衡；

- **FR-9**：`/health` 健康检查 + 5 秒自动重试 + 页面提示条（见 5.3.5）。

## 4.6 特征库数据结构设计

特征库是一个 pickle 序列化的 Python 字典：

```python
star_features.pkl = {
```

设计要点：

1. **键为姓名，值为向量**：查找与遍历都直观；json 不可行（numpy 数组不能直接序列化），故用 pickle；

4. **独立更新**：特征库是独立文件，重建文件 + 重启服务即完成明星库更新，无需重装插件（满足 NFR-4）。

### 5.2.1 配置文件 `backend/config.py`

**职责**：把后端所有"会变的参数"集中到一处管理，避免魔法数字散落在代码里。初学者修改参数只需看这一个文件。

```python

# 服务监听地址（仅本机）
HOST = "127.0.0.1"

# InsightFace 模型
```

**逐段解释**：

- `HOST = "127.0.0.1"`：只监听本机回环地址。127.0.0.1 是每台计算机的"自己"，外部网络无法访问，从网络层面保证隐私（NFR-3）；

- `Path(__file__).resolve().parent`：`__file__` 是当前文件路径，`parent` 取所在目录。这样无论从哪个目录启动，都能正确定位 `data/` 目录，避免"路径写死"问题；
- `SIMILARITY_THRESHOLD = 0.60`：见 2.1 节，阈值语义在 5.4.1 详述；
- `MAX_FACES = 10`：单帧最多返回 10 张脸，防止远景群像图产生大量低质量结果拖慢渲染。

### 5.2.2 识别核心 `backend/recognizer.py`

**职责**：封装"模型加载、特征库加载、人脸识别、缓存"四件事，对外只暴露一个 `recognize()` 方法。Flask 路由不需要关心模型细节。

```python
import hashlib
from collections import OrderedDict

import cv2
import numpy as np
from insightface.app import FaceAnalysis

from config import (DET_SIZE, FRAME_CACHE_SIZE, MAX_FACES, MODEL_NAME,
                    PROVIDERS, SIMILARITY_THRESHOLD, UNKNOWN_NAME)


class FaceRecognizer:
    """封装 InsightFace 检测 + 特征库比对，供 Flask 路由调用。"""

    def __init__(self, db_path, threshold=SIMILARITY_THRESHOLD,
                 model_name=MODEL_NAME, det_size=DET_SIZE):
        self.threshold = threshold
        self.db_path = db_path
        self.embeddings = {}          # name -> 归一化 (512,) float32
        self.model_loaded = False
        self._face_app = None
        self._cache = OrderedDict()   # 内容哈希 -> 识别结果

        self._load_model(model_name, det_size)
        self.load_database(db_path)
```

**构造函数解释**：`__init__` 只做两件事——加载模型、加载特征库，并把结果记录到实例属性中。`embeddings` 字典是特征库在内存中的形态；`_cache` 用 `OrderedDict`（有序字典）实现 LRU 缓存（见 5.4.3）；`threshold`、`db_path` 等由外部传入（app.py 从 config 读取），便于测试时替换。

```python
    def _load_model(self, model_name, det_size):
        try:
            self._face_app = FaceAnalysis(name=model_name, providers=PROVIDERS)
            self._face_app.prepare(ctx_id=0, det_size=det_size)
            self.model_loaded = True
            print(f"[recognizer] InsightFace 模型加载成功: {model_name}")
        except Exception as exc:
            print(f"[recognizer] 模型加载失败: {exc}")
            self.model_loaded = False
```

**容错设计**：模型加载放在 `try/except` 中。即使模型缺失，服务也能启动（`model_loaded = False`），`/health` 会如实上报，`/recognize` 会返回 500 "Model not loaded"，插件据此提示用户——这实现了 FR-9 的"服务状态检测，不崩溃"。

```python
    def load_database(self, db_path):
        """加载 {name: embedding} 特征库并统一归一化。"""
        self.embeddings = {}
        if not db_path or not db_path.exists():
            print(f"[recognizer] 特征库不存在: {db_path}（可运行 build_db.py 构建）")
            return
        try:
            import joblib
            data = joblib.load(str(db_path))
        except Exception:
            import pickle
            with open(db_path, "rb") as f:
                data = pickle.load(f)

        for name, emb in data.items():
            arr = np.asarray(emb, dtype=np.float32).reshape(-1)
            norm = np.linalg.norm(arr)
            if norm > 0:
                self.embeddings[name] = arr / norm
        print(f"[recognizer] 特征库加载完成: {len(self.embeddings)} 位明星 <- {db_path}")
```

**逐段解释**：

- 先尝试用 `joblib` 读取（对 numpy 数组更高效），失败则回退 `pickle`，兼容两种保存格式；
- `np.asarray(emb, dtype=np.float32).reshape(-1)`：无论存的是列表还是数组，统一转成 512 维 float32 数组；
- `arr / norm`：L2 归一化（除以模长），保证后续"点积 = 余弦相似度"（见 2.5）；
- `if norm > 0`：防御零向量（全 0 的特征向量无意义），直接跳过。

```python
    def recognize(self, image_bgr, with_cache=True):
        """输入 BGR 图像，返回识别结果列表。"""
        if not self.model_loaded:
            raise RuntimeError("Model not loaded")

        if with_cache:
            key = self._content_hash(image_bgr)
            if key in self._cache:
                self._cache.move_to_end(key)
                return self._cache[key]

        faces = self._face_app.get(image_bgr)
        results = []
        for face in faces[:MAX_FACES]:
            x1, y1, x2, y2 = [float(v) for v in face.bbox]
            emb = np.asarray(face.embedding, dtype=np.float32)
            norm = np.linalg.norm(emb)
            emb = emb / norm if norm > 0 else emb
            name, conf = self._match(emb)
            results.append({
                "bbox": [int(x1), int(y1), int(x2), int(y2)],
                "name": name,
                "confidence": round(float(conf), 4),
            })

        if with_cache:
            key = self._content_hash(image_bgr)
            self._cache[key] = results
            self._cache.move_to_end(key)
            while len(self._cache) > FRAME_CACHE_SIZE:
                self._cache.popitem(last=False)
        return results
```

**逐段解释**：

- 第2行：模型未加载直接抛异常，由上层路由转成 HTTP 500；
- 缓存部分：先算图像哈希查缓存，命中直接返回（`move_to_end` 是 LRU 的"最近使用"标记）；未命中则走完整识别，最后写入缓存并淘汰最久未用的条目（`popitem(last=False)` 弹出头部）；
- `face.bbox` 是 [x1,y1,x2,y2] 浮点数，转成 int 便于 JSON 传输与前端定位；
- `face.embedding` 同样是归一化后与特征库点积（`_match`）；
- 最终每条结果包含 `bbox`、`name`、`confidence`（相似度分数，四舍五入到 4 位小数）三个字段，与接口约定一致。

```python
    def _match(self, embedding):
        """余弦相似度比对：与特征库中所有向量做点积，取最高分。"""
        best_name, best_score = UNKNOWN_NAME, 0.0
        for name, ref in self.embeddings.items():
            score = float(np.dot(embedding, ref))
            if score > best_score:
                best_score, best_name = score, name
        if best_score < self.threshold:
            return UNKNOWN_NAME, best_score
        return best_name, best_score
```

**算法解释**（这是识别准确性的核心逻辑）：

1. 遍历特征库中每一位明星，计算待识别向量与库向量的点积（即余弦相似度）；
2. 记录最高分及其对应姓名；
3. 若最高分 ≥ 阈值，返回该明星姓名与分数；否则返回"未知"。

**阈值的作用**：假设特征库中有周杰伦，某帧拍到的其实是"长得像周杰伦的素人"，其与周杰伦向量的相似度可能为 0.55，低于阈值 0.60，系统会正确判定为"未知"而不是误报。阈值就是这道"相似度闸门"。

```python
    @staticmethod
    def _content_hash(image_bgr):
        """对 64x64 下采样图取 MD5，作为帧缓存键。"""
        small = cv2.resize(image_bgr, (64, 64))
        return hashlib.md5(small.tobytes()).hexdigest()
```

**解释**：对整张原图做 MD5 太慢且对微小噪声敏感（JPEG 压缩会引入噪声，导致同一帧的哈希也不同，缓存失效）。所以先把图缩到 64×64 再哈希——缩小相当于"模糊"，能容忍轻微噪声；64×64 的 MD5 计算微秒级。这样"暂停播放时画面静止，帧哈希稳定，缓存命中率极高"。

```python
@app.route("/recognize", methods=["POST", "OPTIONS"])
def recognize():
    if request.method == "OPTIONS":
        return ("", 204)
    if not recognizer.model_loaded:
        return jsonify({"error": "Model not loaded"}), 500

    payload = request.get_json(silent=True)
    if not payload or "image" not in payload:
        return jsonify({"error": "Missing 'image' field (base64 data URL)"}), 400

    image_bgr = _decode_image(payload["image"])
    if image_bgr is None:
        return jsonify({"error": "Invalid image data"}), 400

    start = time.perf_counter()
    try:
        faces = recognizer.recognize(image_bgr)
    except Exception as exc:
        return jsonify({"error": f"Recognition failed: {exc}"}), 500

    return jsonify({
        "faces": faces,
        "processing_time": round(time.perf_counter() - start, 4),
    })
```

**逐段解释**（这是一段典型的"接口三段式"：校验 → 处理 → 返回）：

- `request.get_json(silent=True)`：解析 JSON 请求体；`silent=True` 表示解析失败时返回 `None` 而不是抛异常，由下面的判空统一处理；
- 三道防线：模型未加载 → 500；缺 image 字段 → 400；图像解码失败 → 400；
- `time.perf_counter()`：高精度计时器，记录识别耗时写入响应，前端和调试时可直接看到性能数据；
- 识别异常（如内存不足）兜底返回 500，绝不把异常堆栈暴露给前端。

```python
def _decode_image(data_url):
    """解析 data:image/jpeg;base64,xxx 或纯 base64 字符串为 BGR 图像。"""
    try:
        if "," in data_url:
            data_url = data_url.split(",", 1)[1]
        raw = base64.b64decode(data_url)
        arr = np.frombuffer(raw, dtype=np.uint8)
        return cv2.imdecode(arr, cv2.IMREAD_COLOR)
    except Exception:
        return None
```

**解释**：`data:image/jpeg;base64,` 中逗号前是 MIME 头，`split(",", 1)[1]` 取逗号后的纯 base64 部分。`np.frombuffer` 把二进制转成 numpy 字节数组，`cv2.imdecode` 解码成 BGR 图像。任一步失败返回 `None`，由路由转成 400。

### 5.2.4 特征库构建 `backend/build_db.py`

**职责**：把"按姓名分组的明星照片"批量转换成 `star_features.pkl`。这是数据准备阶段的核心脚本。

```python
IMAGE_EXTS = {".jpg", ".jpeg", ".png", ".webp", ".bmp"}


def extract_embedding(face_app, image_bgr):
    """提取图像中最大人脸的特征向量（归一化）。"""
    faces = face_app.get(image_bgr)
    if not faces:
        return None
    face = max(faces, key=lambda f: (f.bbox[2] - f.bbox[0]) * (f.bbox[3] - f.bbox[1]))
    emb = np.asarray(face.embedding, dtype=np.float32)
    norm = np.linalg.norm(emb)
    return emb / norm if norm > 0 else None
```

**解释**：明星照片可能是合照或包含路人。`max(faces, key=...)` 用"边界框宽 × 高"取面积最大的人脸——通常画面主体就是该明星本人，这是个简单有效的启发式策略。

```python
def build(data_dir, output, min_images=3):
    face_app = FaceAnalysis(name=config.MODEL_NAME, providers=config.PROVIDERS)
    face_app.prepare(ctx_id=0, det_size=config.DET_SIZE)

    database = {}
    skipped = []
    for person_dir in sorted(p for p in Path(data_dir).iterdir() if p.is_dir()):
        name = person_dir.name.strip()
        imgs = [p for p in sorted(person_dir.iterdir())
                if p.suffix.lower() in IMAGE_EXTS]
        if len(imgs) < min_images:
            skipped.append((name, f"图片不足 {min_images} 张（{len(imgs)}）"))
            continue

        embeddings = []
        for img_path in imgs:
            img = cv2.imread(str(img_path))
            if img is None:
                continue
            emb = extract_embedding(face_app, img)
            if emb is not None:
                embeddings.append(emb)

        if not embeddings:
            skipped.append((name, "未检测到人脸"))
            continue

        mean = np.mean(embeddings, axis=0).astype(np.float32)
        mean = mean / np.linalg.norm(mean)
        database[name] = mean
        print(f"  [OK] {name}: {len(embeddings)}/{len(imgs)} 张有效")

    output = Path(output)
    output.parent.mkdir(parents=True, exist_ok=True)
    with open(output, "wb") as f:
        pickle.dump(database, f, protocol=4)

    print(f"\n完成: {len(database)} 位明星 -> {output}")
```

**逐段解释**：

- 外层循环遍历 `data/faces/` 下的每个子文件夹，文件夹名即明星姓名；
- 质量过滤：图片不足 3 张、解码失败、未检出人脸的照片都会被跳过并记录原因，保证入库向量可靠；
- **均值融合**：`np.mean(embeddings, axis=0)` 把该明星所有照片的特征向量逐维取平均——不同角度、妆容的特征在空间中"平均"出一个更稳健的代表向量，再归一化后存入库。这就是"每人多张照片"提升识别鲁棒性的原理；
- `pickle.dump(..., protocol=4)`：protocol=4 是兼容性较好的 pickle 协议版本。

### 5.3.2 配置模块 `extension/content/config.js`

**职责**：定义全部可调参数、提供读写 `chrome.storage.sync` 的封装。此文件同时被 content script 和 popup 引用（popup 的 HTML 里用 `<script src="../content/config.js">` 引入），保证两端配置定义唯一、不重复。

```javascript
const DEFAULT_CONFIG = {
  enabled: true,          // 总开关
  threshold: 0.6,         // 相似度阈值
  intervalMs: 300,        // 识别采样间隔（毫秒）
  jpegQuality: 0.7,       // 帧 JPEG 压缩质量
  maxFrameWidth: 960,     // 发送帧的最大宽度
  apiBase: "http://127.0.0.1:5000", // 本地识别服务地址
  showBoxes: true,        // 是否显示人脸框
  unknownLabel: "未知",
};

const CONFIG = { ...DEFAULT_CONFIG };

async function loadConfig() {
  const stored = await chrome.storage.sync.get(DEFAULT_CONFIG);
  Object.assign(CONFIG, stored);
  return CONFIG;
}

function listenConfigChange(callback) {
  chrome.storage.onChanged.addListener((changes, area) => {
    if (area !== "sync") return;
    let changed = false;
    for (const [key, { newValue }] of Object.entries(changes)) {
      if (key in CONFIG) { CONFIG[key] = newValue; changed = true; }
    }
    if (changed && callback) callback(CONFIG);
  });
}
```

**逐段解释**：

- `CONFIG = { ...DEFAULT_CONFIG }`：用展开运算符复制默认值到可变对象，防止运行时修改污染默认配置；
- `chrome.storage.sync.get(DEFAULT_CONFIG)`：**把默认配置作为参数传入**，这是 chrome.storage 的巧妙用法——用户没设置过的键会取默认值，一次调用就完成"合并默认值"；
- `Object.assign(CONFIG, stored)`：把存储值合入内存中的 CONFIG；
- `listenConfigChange`：监听存储变化。用户在 popup 里改阈值，content script 立刻收到通知并热更新，无需刷新页面。`area !== "sync"` 过滤掉本地存储区域的变化，只关心我们用的 sync 区。

### 5.3.3 帧捕获模块 `extension/content/frame-capture.js`

**职责**：定位 B 站播放器 `<video>` 元素，并用 canvas 把当前画面抽成 base64 JPEG。

```javascript
const FrameCapture = {
  SELECTORS: [
    "#bilibili-player video",
    ".bilibili-player-video video",
    "#bilibili-player-wrap video",
    "#bilibiliPlayer video",
    "video",
  ],

  findVideo() {
    for (const sel of this.SELECTORS) {
      const el = document.querySelector(sel);
      if (el && el.videoWidth > 0) return el;
    }
    const videos = document.querySelectorAll("video");
    for (const v of videos) {
      if (v.videoWidth > 0) return v;
    }
    return null;
  },

  capture(video) {
    if (!video || !video.videoWidth || !video.videoHeight) return null;
    const scale = Math.min(1, CONFIG.maxFrameWidth / video.videoWidth);
    const w = Math.max(1, Math.round(video.videoWidth * scale));
    const h = Math.max(1, Math.round(video.videoHeight * scale));
    const canvas = document.createElement("canvas");
    canvas.width = w;
    canvas.height = h;
    const ctx = canvas.getContext("2d");
    if (!ctx) return null;
    ctx.drawImage(video, 0, 0, w, h);
    return { width: w, height: h, dataUrl: canvas.toDataURL("image/jpeg", CONFIG.jpegQuality) };
  },
};
```

**逐段解释**：

- **选择器分层**：`SELECTORS` 数组按"越具体越优先"排列。B 站播放器 DOM 结构多次改版，把选择器集中在这个数组里，页面改版时只需改这一处（对应需求文档的风险应对"使用更稳定的选择器"）；
- `videoWidth > 0`：`<video>` 元素在元数据加载完成前 `videoWidth` 为 0，该判断同时起到"元素存在"与"可播放"双重校验；
- **降采样**：`scale = min(1, 960/videoWidth)`——超过 960px 宽的帧缩到 960px 再发送。识别精度主要取决于人脸在帧中的占比，1080p 视频里人脸区域通常远大于 960px 尺度下的对应大小，所以降采样损失可忽略，却能把传输体积和检测耗时降低约一半；
- `canvas.drawImage(video, 0, 0, w, h)`：**浏览器允许从 `<video>` 元素直接绘制到 canvas**（同源视频），这是"截屏"的标准做法；
- `toDataURL("image/jpeg", 0.7)`：JPEG 质量 0.7 压缩，单帧约几十 KB，本地回环传输几乎无延迟。

```javascript
        "background:" + (known ? "linear-gradient(135deg,#0091ff,#0060d6)" : "rgba(80,80,80,.88)"),
        "color:#fff", `font:600 ${fs}px/1.3 'Microsoft YaHei','PingFang SC',sans-serif`,
        "padding:2px 8px", "border-radius:4px", "white-space:nowrap",
        "text-shadow:0 1px 2px rgba(0,0,0,.4)",
      ].join(";");
      box.appendChild(tag);
      container.appendChild(box);
      labels.push(box);
    }
  }
```

**坐标换算原理（关键）**：后端返回的 bbox 是"发送帧像素坐标"，而标签要画在"屏幕上的视频区域"。由于**覆盖层容器与视频显示区域等尺寸**，只需把像素坐标除以帧宽高得到**百分比**（`px = x1 / frameW * 100`），再以百分比定位即可。这样无论视频被放大缩小到多少像素，百分比天然成立，全屏后依然正确——这就是"百分比坐标自适应"。

**细节设计**：

- `known ? 蓝色 : 灰色`：已知明星标签用蓝色渐变背景，未知用灰色，信息一目了然（FR-8）；
- `py > 14` 时标签通过 `translateY(-100%)` 放在人脸框上方（需求 FR-5 要求"上方"）；人脸贴近视频顶部时自动改为放在框内，避免标签被容器 `overflow:hidden` 裁掉；
- 字号 `container.clientWidth / 70` 随视频宽度自适应，小窗不拥挤、全屏不显小；
- 每帧渲染前先 `clear()` 删除旧标签再重建——简单直接，避免标签累积造成内存泄漏。

### 5.3.5 主控模块 `extension/content/content.js`

**职责**：把前面三个模块串起来的"大脑"——调度识别循环、发送请求、处理状态与容错。这是插件中最复杂的文件，下面按功能拆解。

**（1）初始化与视频探测**

```javascript
(async () => {
  await loadConfig();
  listenConfigChange(onConfigChange);
  chrome.runtime.onMessage.addListener(onMessage);
  watchForVideo();
  setInterval(checkHealth, 5000);
  checkHealth();
})();

function watchForVideo() {
  const tryFind = () => {
    if (video) return;
    const v = FrameCapture.findVideo();
    if (v) { video = v; Overlay.attach(v); startLoop(); }
  };
  tryFind();
  new MutationObserver(tryFind).observe(document.body, {
    childList: true, subtree: true,
  });
  setInterval(tryFind, 3000);   // 兜底轮询
}
```

**解释**：B 站播放器是异步加载的，视频元素可能在脚本注入后很久才出现。方案是"三保险"：① 立即找一次；② `MutationObserver` 监听 DOM 变化（播放器挂载时触发）；③ 每 3 秒兜底轮询一次。一旦找到视频，立即挂载覆盖层并启动识别循环。

**（2）识别主循环（tick）**

```javascript
async function tick() {
  if (!CONFIG.enabled || !video || document.hidden) return;
  if (video.paused || video.ended) {
    if (prevFaces.length) { Overlay.clear(); prevFaces = []; }
    return;
  }
  if (inFlight) return;                    // 上一请求未返回，跳过本次（节流）

  const frame = FrameCapture.capture(video);
  if (!frame) return;

  const key = frame.dataUrl.slice(-64);    // 同帧去重
  if (key === lastFrameKey) return;
  lastFrameKey = key;

  inFlight = true;
  try {
    const faces = await requestRecognize(frame.dataUrl);
    if (video && !video.paused) {
      Overlay.render(smoothFaces(faces), frame.width, frame.height);
    }
    setService(true);
  } catch (err) {
    setService(false, err.message);
    Overlay.clear();
    prevFaces = [];
  } finally {
    inFlight = false;
  }
}
```

**这个函数浓缩了前端的全部性能与容错设计**：

| 行 | 机制 | 解决的问题 |
|----|------|-----------|
| `!enabled / !video / hidden` | 前置过滤 | 关闭、无视频、页面隐藏时零开销 |
| `paused/ended` | 播放状态判断 | 暂停时清空标签，不空转（暂停时画面静止，识别无意义） |
| `inFlight` 标志 | 请求节流 | 模型推理约 100~300ms，若 300ms 定时器触发时上次请求未完成，跳过本次，避免请求堆积 |
| 帧尾 64 字符比较 | 同帧去重 | 暂停或画面静止时帧几乎不变，直接跳过请求（与后端缓存配合双保险） |
| `try/catch/finally` | 容错 | 请求失败只提示不崩溃，下一周期自动重试 |

**（3）请求与健康检查**

```javascript
async function requestRecognize(dataUrl) {
  const resp = await fetch(`${CONFIG.apiBase}/recognize`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ image: dataUrl }),
  });
  if (!resp.ok) {
    const body = await resp.json().catch(() => ({}));
    throw new Error(body.error || `HTTP ${resp.status}`);
  }
  const data = await resp.json();
  return data.faces || [];
}

async function checkHealth() {
  try {
    const resp = await fetch(`${CONFIG.apiBase}/health`, { method: "GET" });
    if (resp.ok) {
      lastHealth = await resp.json();
      setService(true);
    } else {
      setService(false, `HTTP ${resp.status}`);
    }
  } catch {
    setService(false);
  }
}
```

**解释**：`fetch` 是浏览器原生异步请求 API（Promise 风格，配合 `await` 阅读体验如同同步代码）。`requestRecognize` 只负责"发请求、解 JSON、抛错误"，错误语义由调用方统一处理。`checkHealth` 每 5 秒执行一次（见初始化代码的 `setInterval`），是 FR-9 的实现。

**（4）服务状态机与提示**

```javascript
function setService(ok, errMsg) {
  if (ok === serviceOk) return;      // 状态未变化不重复提示
  const wasOk = serviceOk;
  serviceOk = ok;
  chrome.runtime.sendMessage({ type: "SERVICE_STATUS", connected: ok }).catch(() => {});
  if (!ok) {
    showToast(errMsg ? `识别服务错误：${errMsg}` : "识别服务未连接，请先启动本地服务");
  } else if (!wasOk) {
    showToast(`识别服务已连接 · 已入库 ${lastHealth.stars} 位明星`, 2500);
  }
}
```

**解释**：`ok === serviceOk` 提前返回，保证"只在状态翻转时提示一次"，否则每次失败请求都会弹一次提示。提示条（`showToast`）是固定定位在页面右下角的临时通知，几秒后自动淡出，不干扰观看。同时通过 `chrome.runtime.sendMessage` 通知 service worker 更新插件角标。

**（5）人脸平滑去抖**

```javascript
function smoothFaces(faces) {
  const out = [];
  for (const f of faces) {
    const copy = { ...f };
    if (f.name === CONFIG.unknownLabel) {
      for (const p of prevFaces) {
        if (p.name !== CONFIG.unknownLabel && iou(f.bbox, p.bbox) > 0.5) {
          copy.name = p.name;      // 上一帧确认过，本帧闪成"未知"则沿用
          break;
        }
      }
    }
    out.push(copy);
  }
  prevFaces = out;
  return out;
}

function iou(a, b) {   // 交并比：两框重叠程度，0~1
  const x1 = Math.max(a[0], b[0]), y1 = Math.max(a[1], b[1]);
  const x2 = Math.min(a[2], b[2]), y2 = Math.min(a[3], b[3]);
  const inter = Math.max(0, x2 - x1) * Math.max(0, y2 - y1);
  const areaA = (a[2] - a[0]) * (a[3] - a[1]);
  const areaB = (b[2] - b[0]) * (b[3] - b[1]);
  const union = areaA + areaB - inter;
  return union > 0 ? inter / union : 0;
}
```

**解释**：深度学习识别偶尔会"掉帧式闪断"——上一帧正确识别"周杰伦"，下一帧因角度抖动变成"未知"，再下一帧又恢复，造成标签闪烁。解决方案是**时间维度上的迟滞（hysteresis）**：若当前帧某人脸判定为"未知"，但上一帧在相同位置（IoU > 0.5，即两个框大部分重叠）已确认过姓名，则沿用旧姓名。`IoU`（Intersection over Union，交并比）是目标检测领域衡量两个框重叠程度的标准指标，值为 1 表示完全重合、0 表示不相交。

**（6）消息处理**

```javascript
function onMessage(msg, _sender, sendResponse) {
  if (!msg) return;
  if (msg.type === "GET_STATUS") {
    sendResponse({ enabled: CONFIG.enabled, connected: serviceOk,
      stars: lastHealth ? lastHealth.stars : null, threshold: CONFIG.threshold });

}
```

**解释**：popup 打开时通过 `chrome.tabs.sendMessage` 向当前页面的 content script 询问状态（`GET_STATUS`），content script 通过 `sendResponse` 回传。这是 Chrome 扩展消息机制的标准用法。

## 5.4 关键技术实现细节汇总

| 技术点 | 位置 | 一句话原理 |
|--------|------|-----------|
| 余弦相似度比对 | `recognizer._match` | 向量归一化后点积即相似度，逐人扫描取最高分，过阈值才认 |
| 特征均值融合 | `build_db.build` | 同一人多张照片的特征向量取平均，得到更稳健的代表向量 |
| 帧缓存 | `recognizer._cache` | 64×64 缩略图 MD5 作键，LRU 淘汰，静止帧零计算 |
| 请求节流 | `content.tick` | `inFlight` 标志保证同一时刻只有一个请求在途 |
| 同帧去重 | `content.tick` | 帧尾 64 字符比较，画面未变直接跳过 |
| 百分比坐标 | `overlay.render` | 像素 ÷ 帧尺寸 × 100%，容器与视频等尺寸，天然自适应 |
| 尺寸跟随 | `overlay.syncRect` | ResizeObserver 监听视频元素，缩放/全屏自动对齐 |
| 平滑去抖 | `content.smoothFaces` | 相邻帧 IoU 匹配，已知姓名不被单帧"未知"闪断 |
| 断连自愈 | `content.checkHealth` | 每 5 秒探测 /health，状态翻转时提示一次 |
| 播放器探测 | `frame-capture.findVideo` | 分层选择器 + MutationObserver + 兜底轮询三保险 |

## 7.1 工作总结

本文围绕"在 B 站视频中自动识别明星"这一实际需求，完成了一个完整的浏览器插件系统设计与实现。主要工作与成果如下：

1. **完成了需求分析**：将用户需求转化为 9 项功能需求与 6 项非功能需求，并逐项给出实现方案；
2. **完成了系统设计**：确定了"Chrome 插件 + Flask 本地服务"的双端架构，设计了模块划分、HTTP 接口协议与特征库数据结构；
3. **实现了全部功能**：
   - 后端基于 InsightFace 实现了高精度人脸检测与识别，通过余弦相似度比对输出明星姓名；
   - 前端基于 Manifest V3 实现了帧捕获、调度、渲染与设置面板，支持全屏/缩放自适应与断连自愈；
   - 实现了一键启动脚本与特征库构建工具，降低了使用门槛；
4. **完成了系统测试**：接口层自动化测试全部通过，端到端功能测试 11 项全部通过，性能满足指标；
5. **撰写了本论文**：以初学者可理解的方式完整记录了从原理到代码的实现过程，工程代码与论文配套发布。

## 7.2 存在的不足

1. **识别频率与资源占用的平衡**：默认 300ms 采样约 3fps，未完全达到需求文档 NFR-1 的 5fps 目标；
2. **特征库规模受限**：MVP 采用本地固定库，明星覆盖面有限，未匹配人脸只能显示"未知"；
3. **无真实多目标跟踪**：当前采用轻量的帧间去抖，面对快速移动、遮挡切换等复杂场景，标签稳定性不如完整跟踪器（如 ByteTrack）；
4. **模型推理为单帧独立**：未利用视频的时间连续性做批量/复用推理，存在理论上的优化空间。

## 7.3 展望

后续可从以下方向迭代：

1. **场景变化触发识别**：用相邻帧像素差异（如 SSIM 或帧差直方图）判断"画面是否变化"，只在变化时触发识别，可节省 70%+ 的无效计算，从而在相同 CPU 预算下把有效识别频率提升至 5fps 以上；
2. **GPU 加速**：`config.py` 中启用 CUDAExecutionProvider 并配合 onnxruntime-gpu，单帧耗时可从 200ms 降至 20ms 量级；
3. **特征库扩展与热更新**：接入 CN-Celeb 等大规模数据集扩充明星数量；增加 `POST /reload` 接口支持不重启服务热更新特征库；
4. **引入轻量跟踪器**：集成 ByteTrack 等实时多目标跟踪，用跟踪结果关联识别结果，进一步降低重复计算并提升标签稳定性；
5. **发布形态优化**：将 Python 服务打包为单文件可执行程序（PyInstaller）随插件分发，消除用户手动安装 Python 的门槛，甚至提供"免安装一键体验包"。
